# Code language
Always write code in English — identifiers, comments, docstrings, commit messages, branch names — regardless of what language the conversation is in. Exception: user-facing text meant to be read by the end user of the application (UI labels, error messages shown to a user, emails, generated documents) should be written in the target audience's language instead.

# Code comments & documentation
Keep inline code comments minimal — only for non-obvious WHY (a hidden constraint, a workaround, a subtle invariant), never for WHAT the code does. Put substantive information (what something does, how to use it, why it's designed this way) in documentation instead — README, module/API-level docstrings, ADRs — not scattered as inline comments.
